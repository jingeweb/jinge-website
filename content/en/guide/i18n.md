## Configure the compiler

Enable internationalization to let the compiler process `t()` calls and template subscriptions. This workflow includes compile-time message conversion as well as runtime dictionary lookup.

```ts
jingeVitePlugin({ intl: true });
```

## Use translations in components

Messages support parameters and rich text. Template translations update when the locale changes; an ordinary string computed during initialization does not automatically run again.

```tsx
import { t } from 'jinge';

<p>{t('Hello, {name}!', { name: state.name })}</p>;
```

## Initialize dictionaries

Provide a default locale and available dictionaries. A `dictLoader` can load another locale on demand. Await initialization before starting the application and await `intlSetLocale()` when switching.

```ts
import { intlInit, intlSetLocale } from 'jinge';

import zh from './intl/zh';

await intlInit({
  defaultLocale: 'zh',
  dicts: { zh },
  dictLoader: async (locale) => {
    if (locale === 'en') return (await import('./intl/en')).default;
    throw new Error(`Unsupported locale: ${locale}`);
  },
});

await intlSetLocale('en');
```

## The toolchain

`jinge-compiler` provides `intl-extract` and `intl-compile` to extract text and generate dictionary modules. Run `pnpm exec intl-extract --help` and `pnpm exec intl-compile --help` for current options. See the [internationalization example](/examples/i18n/) for the complete structure, dictionaries, and switching behavior.
