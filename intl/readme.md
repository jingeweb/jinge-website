# intl

本目录的两个 CSV 都是**需要提交的翻译源**，但服务对象完全不同。处理器在 `scripts/`，产物 `intl/<locale>.tsx` 是生成文件（已 gitignore）。

## `translate.csv` —— 界面文案

- **管什么**：源码里所有 `t('…')` 调用，即页面、组件、按钮、提示等运行时文案。
- **谁生成**：`scripts/intl.mjs` 跑 `intl-extract` 自动维护。新增 `t()` 会自动追加一行，翻译列留空。
- **列**：`id,file,orig,zh-CN,zh-TW,en`。`id` 是编译器对默认文本算出的 6 位 hash，**不要手改**；改文案会导致 hash 变化。
- **怎么用**：构建时校验三种语言都不为空，缺了直接失败；通过后由 `intl-compile` 生成 `intl/<locale>.tsx`，运行时由 `intlInit` 的 `dictLoader` 按需加载。
- **改翻译**：直接填对应列，不需要改代码。

## `demos.csv` —— 示例源码里的展示文本

- **管什么**：`demos/**` 源码中出现的展示文本（JSX 文本节点、字符串字面量、字典值），例如示例里的按钮文案、列表项、说明句。
- **为什么单独放**：这些不是 `t()` 调用，`intl-extract` 扫不到；它们在构建时由 `scripts/source-i18n.mjs` 的 `localizeSource()` 套用，生成各语言的示例源码副本供 `/examples/<id>/` 展示。
- **列**：`source,zh-TW,en`。`source` 是中文原文，也是查找键；**不要改它**，改了等于改键。
- **怎么用**：`translate()` 查不到会抛错，不会静默回退。
- **改翻译**：填 `zh-TW` / `en` 两列即可。繁中已不再走 OpenCC，与英文一样是人工译文。

## 为什么分成两个

界面文案随 `t()` 调用自动增删，适合工具维护；示例源码的文本嵌在演示代码里，需要开发者判断哪些该翻、怎么断句，且改源码时往往要同步调整译文。混在一张表里会让 `intl-extract` 的自动维护和人工维护互相踩。
